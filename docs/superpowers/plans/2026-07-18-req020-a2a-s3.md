# REQ-020 A2A · S3 Internal Collaboration Plan

> REQUIRED SUB-SKILL: superpowers:subagent-driven-development or executing-plans.

**Goal**:加 a2a_list_sessions 工具(列 a2a_exposed session)+ 白名单字段/UI,让 agent 能发现并委托本机其他 session。

**Architecture**:sessions 表加 a2a_exposed 列(DB migration)。S1 的 a2a MCP 加第 4 个工具 a2a_list_sessions(查 sessionsDb.listA2aExposed)。S2 handleTaskSend 加白名单检查(非 exposed 拒)。UI 侧边栏加"允许 A2A 委托"开关。

**Tech Stack**: TS + better-sqlite3 + Express + React。参照 S1 mcp.route.ts / S2 inbound.service.ts / sessions.db.ts / 会话侧边栏组件。

**执行**: worktree req020-a2a-s3 + subagent-driven(同 S1/S2)。commit --no-verify(husky .bin 缺)。

## Task 4: API PATCH session a2a-exposed

**Files**: server/routes/settings.js(或 sessions 路由,找现有的 session PATCH 位置)

- [ ] Step 1: 加路由:
```js
router.patch('/sessions/:sessionId/a2a-exposed', (req, res) => {
  const { exposed } = req.body || {};
  if (typeof exposed !== 'boolean') return res.status(400).json({ error: 'exposed boolean required' });
  const ok = sessionsDb.setA2aExposed(req.params.sessionId, exposed);
  res.json({ ok });
});
```
(import sessionsDb;确认 settings.js 已挂 /api/settings 且有 authenticateToken,或放别的已 auth 的 sessions 路由)
- [ ] Step 2: typecheck + commit `feat(sessions): PATCH a2a-exposed API(REQ-020 S3)`
