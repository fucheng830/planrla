# Planrla Workbench 新页面需求规格

> 日期: 2026-08-24
> 来源: Workbench light board UI 设计稿
> 范围: 将设计稿中的新页面沉淀为可实施需求
> 关联: `docs/product/PROJECT_WORKBENCH_FUNCTIONAL_REQUIREMENTS.md`, `docs/superpowers/specs/2026-08-23-planrla-workbench-design-system.md`

## 1. 全局页面约束

### 1.1 左侧图标区域不可变

- 所有桌面端子页面必须保留同一套左侧图标导航区域，包括 Planrla 标识、一级导航图标、用户入口和底部设置入口。
- 子页面只能切换左侧图标区域右侧的内容区，不得为单个页面重新定义独立左侧 rail。
- 当前页面通过导航项高亮表达，不通过改变 rail 结构表达。
- 页面滚动、详情抽屉、弹窗、创建面板不得遮挡或重排左侧图标区域。
- 移动端可以折叠导航，但桌面端必须保持固定 rail。

### 1.2 视觉与组件约束

- 新页面必须使用 `workbench-*` 语义色和 `.ds-*` 基础样式。
- 页面以浅色 Workbench 布局为默认视觉目标，同时保留深色 token 的可用性。
- 不新增营销页或说明页，进入页面后直接显示可操作工作区。
- 优先复用现有组件: `Button`, `Card`, `Badge`, `ScrollArea`, `Tooltip`, `Dialog`, Kanban 组件和后台任务组件。
- 新页面的空状态、加载状态、错误状态都必须有明确的下一步动作。

### 1.3 推荐信息架构

```text
Workbench
├─ 项目总览 / Project Overview
├─ 消息盒子 / Message Inbox
├─ 研发流程 / Delivery Workflow
├─ 日历与定时任务 / Calendar & Schedule
├─ 文件中心 / Files
├─ 知识库 / Knowledge
├─ 模型管理 / Models
└─ 设置 / Settings
```

## 2. WB-PAGE-001 项目总览 / Project Overview

### 目标

项目总览用于让负责人在一个页面看到项目目标、整体进度、阻塞点、风险、AI 使用情况和研发阶段推进情况。它是项目级工作台的默认入口。

### 页面布局

- 顶部项目摘要: 项目名称、状态、优先级、负责人、开始日期、目标日期、成员数量、更多操作。
- 项目目标指标区: 总体进度、预期完成率、AI 处理占比、交付质量评分。
- 运行中的智能体: 展示正在执行的 AI 任务、负责人、进度和状态。
- 风险与阻塞: 展示等待确认、阻塞中、高风险事项和最后更新时间。
- 待处理事项: 展示需要人工审批、确认、补充输入或验收的事项。
- 研发流程五阶段: 需求设计、技术方案、开工、测试验证、交付，每个阶段展示完成数、总数、进度和当前阶段高亮。

### 关键动作

- 查看全部指标。
- 查看全部 AI 任务。
- 查看全部风险。
- 查看全部待处理事项。
- 进入研发流程详情。
- 从待处理事项进入消息线程或任务详情。

### 数据需求

- 项目基础信息。
- 项目阶段状态与阶段进度。
- AI 任务列表与运行状态。
- 风险、阻塞和待确认项。
- 需求、方案、任务、验收、交付对象的统计聚合。

### 验收标准

- 用户进入项目后无需打开聊天，即可判断项目是否正常推进。
- 用户能在 1 步内从总览进入阻塞项、待确认消息或当前研发阶段。
- 五阶段流程必须覆盖 `需求设计 -> 技术方案 -> 开工 -> 测试验证 -> 交付`。
- 总览页面不得改变左侧图标导航区域。

## 3. WB-PAGE-002 消息盒子 / Message Inbox

### 目标

消息盒子统一接收外部渠道、人类协作者、AI agent 和系统任务消息，让用户在项目维度处理需要关注的沟通与审批。

### 页面布局

- 左侧二级导航: 频道、项目频道、团队频道、标签、未读和等待处理计数。
- 中间消息列表: 按项目或频道展示线程摘要、发送人、来源、状态、时间和未读标记。
- 顶部筛选器: 全部、未读、进行中、@我、标记、最新排序。
- 右侧详情入口: 点击线程后进入 Thread Detail 或在同页展示预览。

### 消息来源

- 外部 IM: 微信、企业微信、飞书、钉钉、Slack。
- 客服渠道: 闲鱼客服、小红书客服、TikTok 客服、抖音客服。
- 团队协作: 项目成员、组内协作者、负责人、审查者。
- AI 协作: AI 请求人工确认、AI 请求补充材料、AI 提交阶段报告、AI 请求授权。
- 系统消息: 定时任务提醒、一次性任务提醒、日历提醒、交付节点变化。

### 关键动作

- 按频道过滤。
- 按项目过滤。
- 标记已读或未读。
- 标记重要。
- 进入线程详情。
- 将消息转为需求、任务、日程或待确认项。

### 数据需求

- 消息线程、消息、参与者、来源渠道、绑定项目、绑定任务、未读计数。
- 频道接入状态与来源标识。
- 线程状态: 未读、进行中、等待确认、已关闭。

### 验收标准

- 用户能区分消息来自外部客户、团队成员、AI agent 还是系统任务。
- 用户能从消息列表直接定位需要自己处理的线程。
- 消息盒子必须支持按项目和按团队频道查看。
- 消息盒子页面不得改变左侧图标导航区域。

## 4. WB-PAGE-003 消息线程详情 / Thread Detail

### 目标

线程详情用于承载一条协作消息的完整上下文、附件、AI 建议、人工审批和后续动作，避免关键决策散落在普通聊天里。

### 页面布局

- 顶部线程标题: 返回、标题、状态、更多操作。
- 主消息流: 人类消息、AI 回复、附件、版本文件、时间戳和状态。
- 协作请求卡片: 展示 AI 或团队成员要求的人类操作，例如确认、允许、拒绝、补充信息。
- 回复区: 支持回复、内部备注、附件、@人、快捷动作。
- 右侧上下文栏: 消息详情、绑定信息、关联内容、更多操作。

### 关键动作

- 回复线程。
- 添加内部备注。
- 查看附件或版本文件。
- 允许、拒绝或转交协作请求。
- 绑定到项目、任务、需求、日程。
- 关闭线程。
- 查看操作记录。

### 数据需求

- 线程消息详情、附件、参与者、状态历史。
- 绑定项目、绑定任务、绑定需求、来源会话。
- 协作请求对象: 请求人、审批人、截止时间、请求内容、审批结果。
- 关联文件、日程、任务和 AI 运行记录。

### 验收标准

- 用户能在同一页完成阅读上下文、审批请求和回复。
- AI 发起的人类协作请求必须有明确动作按钮。
- 右侧上下文栏必须展示绑定项目和关联内容。
- 线程详情页面不得改变左侧图标导航区域。

## 5. WB-PAGE-004 研发流程 / Delivery Workflow

### 目标

研发流程页面把软件交付过程从聊天和任务列表中抽出来，以五阶段看板方式推进需求设计、技术方案、开工、测试验证和交付。

### 页面布局

- 顶部项目标题与状态。
- 视图切换: 看板视图、列表视图。
- 筛选与更多操作。
- 五阶段看板列:
  - 需求设计
  - 技术方案
  - 开工
  - 测试验证
  - 交付
- 每张任务卡展示: 标题、负责人、优先级、进度、状态、等待确认标记。
- 底部图例: 未开始、进行中、待确认、已完成、阻塞中。

### 关键动作

- 新建任务。
- 拖动任务切换阶段。
- 打开任务详情。
- 设置负责人、优先级、状态和截止时间。
- 查看阶段统计。
- 切换列表视图。

### 数据需求

- 交付阶段定义。
- 任务、需求、方案、验收对象及其阶段映射。
- 负责人、优先级、进度、阻塞状态。
- 阶段内排序。

### 验收标准

- 五阶段名称和顺序必须固定为 `需求设计 -> 技术方案 -> 开工 -> 测试验证 -> 交付`。
- 每个阶段能显示完成数、总数和阶段内任务卡。
- 任务卡能表达负责人、优先级、状态和进度。
- 看板页面应优先复用现有 Kanban 能力。
- 研发流程页面不得改变左侧图标导航区域。

## 6. WB-PAGE-005 日历与定时任务 / Calendar & Schedule

### 目标

日历与定时任务页面统一管理项目会议、提醒、定时任务、一次性任务和 AI 自动推进计划，让人类协作点与自动化执行点都可见。

### 页面布局

- 顶部月份导航: 上月、下月、当前年月、今天。
- 视图切换: 月、周、日。
- 月历区域: 展示日期、事件、会议、任务和更多事件入口。
- 右侧日程列表: 展示选中日期的会议、提醒、任务和关联议题。
- 右侧创建面板:
  - 新建定时任务
  - 新建一次性任务

### 定时任务字段

- 任务名称。
- 重复规则: 每天、每周、每月、自定义。
- 时间。
- 开始日期。
- 结束日期。
- 执行内容。
- 通知方式: 站内消息、邮件、飞书或其他已接入渠道。

### 一次性任务字段

- 任务名称。
- 执行时间。
- 时长。
- 参与人。
- 提醒时间。
- 备注。
- 绑定项目、需求、任务或消息线程。

### 关键动作

- 切换月份、周、日。
- 选择日期查看日程。
- 新建定时任务。
- 新建一次性任务。
- 编辑或取消任务。
- 将任务绑定到消息线程或研发流程任务。

### 数据需求

- 日历事件、定时任务、一次性任务、会议和提醒。
- 参与人、通知渠道、绑定对象。
- 执行状态: 待执行、已执行、失败、已取消。

### 验收标准

- 用户能在日历中同时看到会议、人类协作提醒和 AI 自动任务。
- 用户能创建每日重复类定时任务。
- 用户能创建指定时间执行的一次性任务。
- 定时任务和一次性任务必须能绑定到项目上下文。
- 日历页面不得改变左侧图标导航区域。

## 7. 复用与实现优先级

### 7.1 可复用能力

- 左侧图标导航: 从现有 Sidebar/WorkbenchRail 抽象复用。
- 研发流程: 复用现有 Kanban 组件和任务状态组件。
- 日历任务: 复用 BackgroundTasks 的任务状态、创建和执行结果表达。
- 消息详情: 复用现有聊天消息、附件、文件 chip、审批 banner 和 composer。
- 状态表达: 复用 `workbench.css` 中的 status token。

### 7.2 第一阶段实施顺序

1. 固定 Workbench 信息架构与左侧 rail。
2. 实现项目总览只读聚合页。
3. 实现研发流程看板页。
4. 实现消息盒子列表与线程详情。
5. 实现日历与定时任务页。
6. 串联消息、任务、日历和项目对象之间的绑定关系。

### 7.3 非目标

- 第一阶段不实现所有外部渠道真实接入，仅需要保留渠道模型、来源标识和接入状态。
- 第一阶段不实现复杂权限矩阵，只需支持负责人、成员和 AI 请求审批的基础角色表达。
- 第一阶段不改变现有会话执行、Provider 调用和 WebSocket 数据流。
