# v1 UX 与信息架构梳理

## 设计目标

v1 的交互目标是让用户始终清楚三件事：

1. 当前在哪个项目。
2. 当前查看哪个会话或任务。
3. 任务现在处于什么状态，是否需要自己处理。

## 主路径

```text
项目列表 -> 会话列表 -> 对话详情 -> 文件/Git/终端/任务辅助面板
```

主界面不应该同时暴露过多同级入口。用户的主要心智模型应是：

- 先选项目。
- 再选会话。
- 围绕会话查看 Agent 输出、文件变更、Git 状态和终端。

## 主界面分区

### Sidebar

职责：

- 项目选择。
- 会话选择。
- 运行中任务入口。
- 新完成任务提醒。
- 归档和搜索入口。

Sidebar 不承担复杂配置，不展示低频高级设置。

### Main Content

职责：

- Chat：核心对话与任务执行。
- Files：项目文件浏览和编辑。
- Git：变更查看、提交、同步。
- Shell：项目终端。
- Tasks/Browser/Plugins：辅助能力，按需展开。

### Settings

职责：

- 常用设置：外观、通知、Provider、License。
- 高级设置：工具权限、MCP、插件、Browser Use、语音等。
- 危险操作必须分组并增加确认。

## 任务状态展示

所有端统一展示以下状态：

- `running`：运行中，显示动效和可中断入口。
- `waiting_for_input`：等待用户输入或授权，必须高亮。
- `completed`：刚完成，显示新完成标记，用户点击会话后清除。
- `failed`：失败，需要显示失败标记和错误详情入口。
- `needs_attention`：需要关注，例如部分完成、人工确认、环境异常。

## 会话列表原则

- 默认倒序：最新活动在上。
- 新完成会话置于用户可见位置，并带状态标记。
- 用户点击会话后清除新完成标记。
- 运行中会话可以从 Running 过滤入口快速访问。
- 对话搜索和普通会话列表分离，避免搜索状态污染主列表。

## 设置页原则

设置页按用户任务组织，而不是按代码模块组织：

1. Account & License
2. Providers
3. Appearance
4. Notifications
5. Tools & Permissions
6. Plugins
7. Advanced

P0 阶段先完成梳理和命名，后续再逐步调整实际 UI。

## Android 端定位

Android 不做完整 IDE，而是专注：

- 查看项目和会话。
- 接收任务完成提醒。
- 继续对话。
- 处理权限请求。
- 查看关键文件变更和 Git 摘要。

桌面端仍是重度操作中心，Android 是移动接管和提醒入口。

## P0 已落地项

- Android 已纳入 `apps/android` 工作区。
- 新增统一任务状态模型。
- 会话列表展示运行、等待、完成、失败状态。
- 新完成提醒在用户点击会话后清除。
- 长会话消息列表增加窗口化渲染。

## 后续 UI 调整

- 重新组织 Settings 实际 tab 顺序。
- 为 `waiting_for_input` 增加更醒目的全局入口。
- 将 Provider 能力声明驱动到模型选择、权限按钮和设置项展示。
- 为 Android 输出精简版信息架构。
